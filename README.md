# 졸업사정 자가체크

가톨릭대학교 특수교육과 학생이 **졸업 요건을 스스로 점검**할 수 있는 웹 앱입니다.
학과에서 스프레드시트로 운영하던 자가체크 리스트를 웹으로 옮기고, 입학년도·이수 유형별로 달라지는 복잡한 규칙을 자동으로 판정하도록 만들었습니다.

- **데모**: <https://journeyss-dev.github.io/graduation/>
- **HTML 한 파일 버전** (내려받아 오프라인 사용): <https://journeyss-dev.github.io/graduation/graduation.html>
- **기술**: React · JavaScript · Vite · GitHub Actions / Pages
- **개발 방식**: 요구사항 정의와 검증은 제가, 구현은 AI(Claude)와 단계별로 협업했습니다. ([개발 과정](#개발-과정과-ai-활용) 참고)

> 이 서비스의 결과는 참고용입니다. 정확한 졸업 여부는 학과 홈페이지와 학과 조교를 통해 확인해야 합니다.

## 1. 문제와 해결

| | 기존 (스프레드시트) | 이 프로젝트 |
|---|---|---|
| 접근성 | 파일 복사본을 받아 직접 수정 | 링크 하나로 접속, 모바일 지원 |
| 규칙 변경 | 학번마다 시트를 따로 관리 | 규칙을 데이터로 분리해 학번별로 자동 적용 |
| 복잡한 규칙 | 학생이 직접 계산 (중복과목, 성적표 학점 등) | 자동 판정 + 부족한 항목을 문장으로 안내 |
| 운영 비용 | 학과에서 시트 배포·관리 | 서버 없는 정적 페이지, 유지비 0원 |

## 2. 주요 기능

- **입학년도 · 이수 유형별 자동 판정**: 제1전공심화 / 부전공 / 복수전공 2종, 총 9~10개 졸업 요건
- **요건별 체크 화면**: 과목을 체크하면 즉시 이수 여부와 진행률이 갱신
- **"아직 남은 일" 요약**: 미이수 요건마다 무엇이 얼마나 부족한지 안내
- **체크한 과목 한눈에 보기**: 영역별로 정리해 인쇄·PDF 저장 (인쇄 시 자동으로 펼침)
- **자동 저장과 백업**: 브라우저에 자동 저장, JSON 파일로 내보내기/불러오기
- **다크모드(기본) · 밝은 화면**, 모바일·데스크톱 반응형 UI
- **두 가지 배포 형태**: 웹 주소 접속 / HTML 한 파일 다운로드

## 3. 기술적으로 신경 쓴 부분

### 규칙 데이터 · 판정 로직 · 화면의 분리
졸업 기준은 해마다 바뀔 수 있습니다. 그래서 학점 기준과 과목 목록은 `src/rules/`의 **데이터**로, 판정은 `src/logic/`의 **화면과 무관한 순수 함수**로, 화면은 `src/components/`로 나눴습니다.
기준이 바뀌면 데이터 파일만 고치면 되고, 판정 로직은 화면 없이 테스트할 수 있습니다.

### 저장하는 것은 "입력값"뿐, 결과는 매번 계산
이수 여부 같은 파생 값은 저장하지 않고 입력값에서 매번 계산합니다. 규칙이 바뀌어도 저장된 값과 결과가 어긋나지 않고, 저장 구조가 단순해집니다.
저장 데이터에는 버전 번호를 넣어 구조가 바뀌어도 안전하게 복원하고, 깨진 데이터는 오류 없이 초기 상태로 시작합니다.

### 서로 얽힌 규칙의 모델링 (중복과목)
직업교육 39학점과 특수교육 42학점을 합치면 81학점이지만, 양쪽에 동시에 인정되는 "중복과목"(최대 5과목 15학점) 때문에 성적표 학점은 66학점이 됩니다.
"어느 쪽에서 선택했는지에 따라 인정 방식이 달라지는 과목", "한도 초과 시 초과분 처리" 같은 예외까지 한 모듈(`logic/major.js`)에서 계산하고, 테스트로 고정했습니다.

### 서버 없는 구조의 제약 다루기
서버가 없으므로 모든 데이터가 학생 브라우저에만 있습니다. 대신 백업 파일 내보내기/불러오기를 제공하고, 입력 내용이 외부로 전송되지 않는다는 점을 안내 화면에 명시했습니다.

### 테스트와 배포 파이프라인
- 판정 로직 단위 테스트 **34개** (`npm test`)
- 규칙 데이터의 학점 합계가 서로 맞는지 점검하는 스크립트 (`npm run check:rules`)
- GitHub Actions: `main`에 push하면 **테스트 → 빌드 → 배포**가 자동 실행되고, 테스트가 실패하면 배포되지 않습니다.

## 4. 구조

```
src/
├─ rules/        학점 기준 · 과목 목록 (데이터)
├─ logic/        졸업 판정 (순수 함수) + 단위 테스트
├─ storage/      브라우저 저장 · 백업 파일 읽기/쓰기
├─ hooks/        저장 상태 · 화면 모드 관리
├─ components/   화면 (안내 · 선택 · 현황 · 요건별 체크)
└─ App.jsx       화면 전환
```

```
 rules (기준 데이터) ─┐
                      ├─▶ logic/evaluateGraduation ─▶ 요건별 이수 여부 · 부족분 ─▶ 화면
 학생 입력 (저장됨) ──┘
```

| 영역 | 핵심 파일 |
|---|---|
| 판정 | `logic/evaluateGraduation.js` (종합), `major.js` (특수교육·표시과목·중복과목), `teaching.js`, `liberalArts.js` |
| 입력 모델 | `logic/studentState.js` |
| 화면 문구 | `logic/summary.js` (요약·남은 일), `logic/overview.js` (체크 내역) |
| 저장 | `storage/studentStorage.js` |

## 5. 로컬에서 실행하기

```
npm install
npm run dev            # 개발 서버 (http://localhost:5173)
npm test               # 단위 테스트
npm run build          # 웹 배포용 빌드 → dist/
npm run build:single   # HTML 한 파일 빌드 → dist-single/index.html
```

> Windows PowerShell에서 `npm`이 막혀 있으면 `npm.cmd`로 실행하세요.

## 6. 배포

- **GitHub Pages**: `.github/workflows/deploy.yml` 이 `main` push 시 자동 배포합니다. 같은 빌드에서 HTML 한 파일(`graduation.html`)도 함께 올립니다.
- **HTML 한 파일**: `vite-plugin-singlefile`로 JS·CSS를 `index.html` 하나에 합친 빌드(약 290KB)입니다. 더블클릭만으로 오프라인에서 실행됩니다.

## 7. 개발 과정과 AI 활용

이 프로젝트는 **AI(Claude)와 협업**해서 만들었습니다. 역할은 이렇게 나눴습니다.

- **제가 한 일**: 졸업 요건 정의와 예외 규칙 설명, 기존 스프레드시트·학과 규정 대조, 기능·UI 요구사항 결정, 각 단계 직접 실행과 검증, 수정 요청, 배포 설정(GitHub Pages)
- **AI가 한 일**: 구조 설계 제안, 코드 작성, 테스트 작성, 문서화

진행은 "규칙 데이터 정리 → 판정 로직과 테스트 → 화면 → 저장/백업 → 다듬기 → 배포" 순서의 단계로 나눠서, 매 단계마다 직접 실행해 결과를 확인하고 피드백했습니다.
도메인 규칙(중복과목, 복수전공 예외 등)은 제가 설명한 내용을 테스트 케이스로 옮겨서 구현이 맞는지 검증했습니다.

## 8. 한계와 향후 계획

- 졸업 요건은 학교 규정에 따라 달라질 수 있어, 결과는 참고용입니다.
- 입력은 브라우저마다 따로 저장됩니다. (백업 파일로 이전 가능)
- 향후: 요건 기준 변경 이력 관리, 접근성(스크린리더) 점검 확대, 성적표 자동 인식 검토
